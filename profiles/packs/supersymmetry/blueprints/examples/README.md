# Supersymmetry Blueprints examples

This directory contains developer-facing requests selected for the
Supersymmetry pack profile. The examples are intentionally
non-identity-bearing: they do not add construction authority, profile support,
action authorization, or release approval.

List the allowlisted records with `workbench feature examples`. To translate
one record through its current owner Blueprint without mutating the checkout,
run:

```text
workbench feature plan --example EXAMPLE_KEY WORKSPACE
```

Automation can append `--compact-json` to receive only the validated example
applicability, retained plan URI, plan ID, review counts, and current
transaction state. The compact projection deliberately omits Base64 operation
bytes and unified diffs; the ordinary retained owner plan remains the authority
for review and later consent.

The result retains the ordinary family plan, reports how the current Git
revision relates to any historical base/result revisions, and identifies
owner-derived values that changed for the current checkout. Applying still
requires the existing family command and consent to the exact retained plan
ID. An already-present recipe or quest edge remains an owner-planner failure;
the example command does not weaken duplicate, no-op, validation, or consent
checks.

[`material-fluid-recipe-radon.json`](material-fluid-recipe-radon.json) is the
current known-good combined material, fluid, localization, and bounded recipe
example. Its retained client run observed all six assertions for one exact
disposable projection. Reuse still requires current target capture, collision
checks, exact diff review, and the checks appropriate to the selected action.

[`recipe-change-copper-sulfate-solution.json`](recipe-change-copper-sulfate-solution.json)
extracts one useful MIXER addition from Supersymmetry pull request 1451. It is
bound to the effective base, merge result, owner path, and before/after Git
blobs. The pull request also added a batch-reactor recipe and changed nearby
whitespace; those changes are deliberately outside this example. The current
Blueprint can add a recipe transactionally, but this exact request has no
retained current Cleanroom client or dedicated-server observation.

[`quest-for-process-gas-atomizer.json`](quest-for-process-gas-atomizer.json)
extracts the Gas Atomizer prerequisite edge from pull request 1978. It records
the exact quest file and blob transition from prerequisite `757` to
`[757, 90454916]`, with a parallel `IMPLICIT` requirement type. The current
Blueprint validates the new edge and edits existing localization keys when
requested. It does not certify pre-existing graph health, BetterQuesting
runtime loading, player detection, or retained world state.

The two revision-bound examples describe changes already present after their
named result revisions. Their effective bases bind historical provenance; they
are not guaranteed to satisfy the current Workbench Packwiz profile and should
not be treated as directly runnable product targets. Use a compatible
disposable fixture or current checkout, adapt the request to a genuinely new
recipe or quest edge, and let duplicate/no-op checks fail closed.
