# Exact Runtime Explorer V1

`workbench explore` turns an identity from source, an artifact, a log, or a
controlled capture into an authority-labeled result. It keeps static
possibility, observed behavior, presentation evidence, and teaching distinct.

```bash
workbench explore example:machine
workbench explore class:gregtech.api.GTValues --artifact PATH/gtceu.jar --details
workbench explore mixin:example.MixinTarget --receipt RECEIPT.json --sources
```

With no query, an interactive terminal offers the same owner-backed route as
`explorer.search`. JSON output is the complete validated result; terminal
output is a sanitized presentation of it.

## Composition

```text
query or source location
          |
          v
Project Intelligence ---- exact static source and artifact structure
Atlas ------------------- accepted assembled-game knowledge
Crucible ---------------- controlled runtime records and capture limits
retained logs ----------- presentation evidence
Manuals ----------------- teaching
          |
          v
Workbench exact joins, ranking, and navigation
```

Project Intelligence reads files and class archives without loading code.
Atlas remains the observed and derived knowledge authority. Crucible retains
controlled occurrences. Manuals explains. Explorer creates neither a truth
store nor an approval path.

## Inputs and facets

The bounded workspace scanner discovers conventional nested source, resource,
configuration, and script roots while pruning generated and private trees. It
records declarations, members, Mixins and targets, registry/resource
literals, JSON identities, recipes, loot, configuration keys, and Groovy
declarations with file hashes and line navigation. Its lexical results are
static observations, not proof of execution.

The archive scanner records exact JVM and resource structure from one JAR or
ZIP: classes, inheritance, fields, methods, descriptors, references, source
lines, strings, resources, entry hashes, ownership candidates, and Mixin
topology. It never defines classes or selects a classpath.

Atlas facets come from immutable query projections and retain profile, side,
node identities, ownership, relationships, projection identity, and
truncation. Known Crucible adapters validate their receipt type before
projecting exact launch, transformation, class-definition, service, loader,
provider, and coverage observations. Unknown receipt types remain bounded
verbatim evidence and are never promoted to interpreted behavior.

Retained console sessions and logs can contribute exact events, stack frames,
coordinates, namespaced identities, severity, and unresolved source
candidates. Incomplete sessions remain partial. Serialized source paths are
recorded evidence; they are not assertions that the same local bytes still
exist.

Pack Program results remain source-bound: static effects are
`static-possible`; compiler diagnostics are exact for the checked in-memory
bytes but have `runtime_form.state = not-observed`. Compiler acceptance does
not prove script execution or an effective registry change.

## Exact joins and ambiguity

The query interpreter recognizes typed identities for code, JVM members,
registries, resources, recipes, blocks, items, configurations, events,
capabilities, coordinates, profiler events, Mixins, and source locations.
Ranking is deterministic. Facets join only through declared strong exact
identities, never fuzzy similarity.

A joined entity preserves every source facet and its authority. An observed
facet does not upgrade a static one. Multiple exact owners, Atlas nodes,
artifacts, profiles, or sides remain explicit ambiguity. Missing runtime
coverage produces an uncertainty state, not an empty success.

The V1 JSON validator recomputes entity identities, merged evidence
projections, authority bindings, ambiguity, coverage, counts, limitations,
truncation, status, and final result identity.

## Graph-native presentation

The embedded graph-native presenter executes one exact registered
`graph/query` through the trusted Crucible service and returns the canonical
owner-result bytes. Its optional terminal renderer may sanitize and format
those rows, but does not wrap or reinterpret them as Explorer V1 facets.

Only the in-process registered route carries presenter authority. Bare JSON,
saved RPC output, arbitrary endpoints, and standard input do not. The route
does not acquire a writer lease, move a publication reference, or open raw
worldgen evidence.

The trusted host producer mints the binding from its current native/source
registration. Explorer validates that owner capability without importing
Shell or comparing installed metadata against a frozen source-only hash.

The contract is
[graph-native presentation V2](../../modules/runtime-explorer/contracts/graph-native-presentation-v2.md).

## Safety and custody

Explorer is read-only. It does not execute archives, launch Minecraft,
download sources, or mutate `.workbench`. It rejects symlinked or replaced
inputs, unsafe archive members, live SQLite journals, malformed receipts, and
inputs above declared size or record limits. Atlas databases are opened
query-only in immutable mode.

The composition bounds explicit inputs, source count, archive count and total
bytes, file scans, receipt size, and projected record count. When a source cap
is reached, the result reports incomplete coverage. Large runtime captures
belong behind an immutable Atlas query projection rather than an unbounded
in-process JSON load.

All human-readable values pass through the terminal sanitizer. JSON output
retains the structured values with JSON escaping.

## Claim boundary

Explorer can show exact static structure, accepted knowledge, controlled
occurrences, presentation evidence, and navigation together. It does not
infer load or execution from a name match, reconstruct causality from logs,
claim that a registered machine formed in a world, or convert a bounded
runtime result into global truth.

Artifact and receipt inputs remain explicit. A local checkout is never
silently treated as the assembled game.

The serialized result is defined by the
[Exact Runtime Explorer V1 contract](../../modules/runtime-explorer/contracts/exact-runtime-explorer-v1.md).
